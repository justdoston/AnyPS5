# libSceJxr technical debt

### GUID exports

- [GUID data exports](../../../core/libs/prx/libSceJxr/src/GuidExports.cpp) use 84 values from the pinned JXR header. Their NIDs and bytes match version-labelled images; the labels are not authenticated. Runtime behavior on a console and complete consumer coverage are unverified. Four additional 4-byte interface identifiers have names and values matching the pinned upstream JXR implementation and both version-labelled images; their relative placement in a guest image and use by consumers are unverified. One older 8-byte writable object has a relocation and no matching later-image data export; its identity, lifetime and initialization remain unknown and it is not implemented.

### Functional

- [PixelFormatLookup](../../../core/libs/prx/libSceJxr/src/PixelFormatLookup.cpp) uses pinned public jxrlib through a C bridge and a 56-byte LP64 guest record. [BunnyFl reports firmware 13.42 native-PC comparisons](https://github.com/boykopovar/AnyPS5/pull/9954#issuecomment-6406356097): the 68 table entries match public jxrlib, and return values/record fields match across 802 cases repeated three times, except that the module clears padding bytes 28..31 on all 309 successes. This bridge now clears that four-byte range explicitly on success; it does not copy indeterminate C++ padding. This is attributed single-firmware evidence, not an author-run console measurement or proof of the complete Sony ABI/configuration. Module/library versions, other firmware and valid-mode null arguments remain unverified. Modes 0/1 perform forward GUID/reverse TIFF lookup; other modes and misses leave the entire record unchanged. Valid-mode null records and forward null GUIDs remain explicitly unsupported. Success borrows a read-only static GUID while the module is loaded; callers must not free it. Closes when: remaining Sony ABI, version/configuration and invalid-argument behavior are verified by attributable measurements or disassembly

- [PKFree](../../../core/libs/prx/libSceJxr/Export.cpp) (libSceJxr) follows Microsoft's jxrlib [JXRGlue.c](https://github.com/4creators/jxrlib/blob/f7521879862b9085318e814c6157490dd9dbbdb4/jxrgluelib/JXRGlue.c#L53-L62), whose four exported names the module shares: a non-null `ppv` has `*ppv` released with the guest `free` and set to null, and the result is always `WMP_errSuccess` (0) as a 64-bit `ERR` (`long`). That the console's module is built from jxrlib, and that its `PKFree` releases through libc's `free`, is inferred from the export names and not checked against the console's code. Closes when: the console's `PKFree` is disassembled or measured on a PS5

- [readIS and writeIS](../../../core/libs/prx/libSceJxr/Export.cpp) use the non-ARM, LP64 `BitIOInfo` and `WMPStream` ABI and packet algorithm from [Microsoft's JPEG XR reference implementation](https://github.com/4creators/jxrlib/blob/f7521879862b9085318e814c6157490dd9dbbdb4/image/sys/strcodec.c#L1090-L1177). Console structure layouts and execution remain unverified. Profiling callbacks are omitted as in the reference Unix build with `DISABLE_PERF_MEASUREMENT`; the codec argument is unused. Where the reference uses an invalid pointer, `std::invalid_argument` is thrown instead: a null bit state, stream or callback, a read-only read packet, and a null packet when a read copies its shadow or a successful write offsets it; a null packet still reaches the callback first. No codec is instantiated by these helpers; callers must supply the reference ring buffer and guest-ABI stream callbacks.

- [Streams, allocators and bit I/O](../../../core/libs/prx/libSceJxr/src/StreamIo.cpp) - 47 exports follow jxrlib's [strcodec.c](https://github.com/4creators/jxrlib/blob/f7521879862b9085318e814c6157490dd9dbbdb4/image/sys/strcodec.c) and [JXRGlue.c](https://github.com/4creators/jxrlib/blob/f7521879862b9085318e814c6157490dd9dbbdb4/jxrgluelib/JXRGlue.c) on the LP64 `WMPStream`, `BitIOInfo` and `SimpleBitIO` layouts; console execution is unverified. Where jxrlib shifts a 32-bit value by 32 or more, the count is taken modulo 32 as x86 does; what the console's compiled module does is unverified. `PKAllocAligned` throws for an alignment of 0 and where jxrlib would store the original pointer before the block (a correction under 8 bytes, as for alignments 1 and 2). Null pointers that jxrlib dereferences throw. The codec argument of `attachISRead`, `detachISRead`, `detachISWrite` and `getBit16_S` is ignored, as in a build without performance measurement.

- [Codec helpers](../../../core/libs/prx/libSceJxr/src/Codec.cpp) - `slideOneMBRow`, `updatePostProcInfo`, `postProcMB`, `postProcBlock`, `remapQP`, `formatQuantizer` and `getACPredMode` call the pinned jxrlib through [NativeCodec.c](../../../core/libs/prx/libSceJxr/src/NativeCodec.c) on the LP64 post-processing, quantizer and macroblock records, which hold no `long` or `size_t` field; `initPostProc`, `termPostProc`, `allocateQuantizer`, `freeQuantizer` and `FreeDescMetadata` are adapted to the guest allocator. Console behavior is unverified. `GetPixelFormatFromHash` returns the exported GUID object with the bytes jxrlib finds. For `.wdp` and `.hdp`, `GetImageEncodeIID` returns a private `IID_PKImageUnsupported` (100), which the module does not export. `FreeDescMetadata` throws for the variant types jxrlib asserts on, `DPKVT_UI1` included. Null pointers that jxrlib dereferences throw.

- [Codec state](../../../core/libs/prx/libSceJxr/src/CodecState.cpp) - 20 exports take the pinned jxrlib's LP64 `CWMImageStrCodec` (35944 bytes) as built here, without performance measurement; a console build with it moves `pPostProcInfo` and the fields after `m_bSecondary`, which these exports do not read. Console behavior is unverified. `checkImageBuffer`, `getTilePos`, the macroblock-row pointer helpers, `setBitIOPointers`, the quantizer selectors, `getDCACPredMode`, `updatePredInfo`, `InitZigzagScan` and `ResetCodingContext` call jxrlib through [NativeCodecState.c](../../../core/libs/prx/libSceJxr/src/NativeCodecState.c); `allocateBitIOInfo`, `allocateTileInfo`, `freeTileInfo`, `allocatePredInfo`, `freePredInfo` and `AllocateCodingContextDec` are adapted there to the guest allocator. The adaptive Huffman tables they point to are the library's own copies. Null codecs throw, except where jxrlib checks for them.

- [Image objects](../../../core/libs/prx/libSceJxr/src/Glue.cpp) - the generic `PKImageDecode`, `PKImageEncode`, `PKFormatConverter`, `PKFactory` and `PKCodecFactory` functions take the LP64 objects of the pinned jxrlib (66584, 66688 and 96 bytes), whose generic fields precede its `Long` members; console behavior is unverified. Their method tables hold the module's exports. `PKCodecFactory_CreateCodec`, `PKCodecFactory_CreateDecoderFromFile`, `PKFormatConverter_Initialize`, `PKFormatConverter_InitializeConvert` and the `_WMP` functions still throw, so a converter cannot be initialized and no JPEG XR decoder or encoder can be created yet. `PKFormatConverter_EnumConversions` returns the exported GUID object with the bytes jxrlib finds. Null pointers that jxrlib dereferences throw.

- The 13 additional exports in [Export.cpp](../../../core/libs/prx/libSceJxr/Export.cpp) are present in the pinned firmware 13.60 `libSceJxr` export inventory. Their parameter lists, return types and behavior are unverified. Parameterless `int` declarations are import-resolution placeholders, not verified ABI prototypes; every entry throws through `NotImplemented_nid_no_patch`. The `_nid_postfix` aliases keep the guest bindings distinct from private native helpers. No runtime functionality is implemented.
